# 01-03 引用

> 标准：C++98（右值引用 `&&` 见 [02-03](../part2_memory/02-03_move_semantics.md)）
> demo：[`01_03_reference.cpp`](../../demos/part1_basics/01_03_reference.cpp)

## 一、解决了什么问题

C 里想让函数修改调用方的变量，只有一条路：传指针。

```c
void swap(int* pa, int* pb) {
    if (!pa || !pb) return;          /* 每次都要防空 */
    int tmp = *pa; *pa = *pb; *pb = tmp;
}
swap(&a, &b);                        /* 调用方要记得取地址 */
```

能用，但有三处摩擦：

1. **调用方要写 `&`，函数体里到处是 `*`** —— 语法噪声掩盖了逻辑
2. **指针可以为空，也可以中途改指向** —— 所以每个函数都得防御性检查
3. **传大对象时，值传递会拷贝整个对象** —— 想避免拷贝就只能用指针，于是问题 1、2 又回来了

引用的设计目标是：**获得指针的效率（不拷贝、能改原值），但语法上像直接操作变量，
并且去掉"可空"和"可改指向"这两个自由度**。

```cpp
void swap(int& x, int& y) {          // 不可能为空，无需检查
    int tmp = x; x = y; y = tmp;     // 像操作普通变量
}
swap(a, b);                          // 调用方什么都不用加
```

## 二、什么是引用

变量名本质上是一段内存的别名。那一段内存只能有一个别名吗？不一定 ——
**引用就是已定义变量的另一个别名**。

```cpp
类型 & 引用名 = 目标变量名;

int a = 1;
int& ref1 = a;      // ref1 是 a 的别名
```

使用引用要注意四点：

1. `&` 在这里不是取地址符，而是引用符号 —— `&` 有了第二种含义
2. 引用的类型必须和绑定的变量类型相同
3. **声明引用的同时必须初始化**，否则编译报错
4. **一旦绑定就不会再改变指向**

第 4 点最容易出错。下面这行不是"重新绑定到 b"，而是"把 b 的值赋给 a"：

```cpp
int b = 2;
ref1 = b;      // 等价于 a = b
```

实测输出证实了地址没变：

```
a=100 ref1=100
&a=0x7ffc78a69068 &ref1=0x7ffc78a69068  (地址相同)
ref1 = b 之后: a=2 &ref1=0x7ffc78a69068 (仍是 a 的地址)
```

取引用的地址，得到的是被引用对象的地址 —— 引用在语法上**彻底透明**。

## 三、引用的本质（常考题）

常见说法有两种，一种说"引用只是别名，不占内存"，一种说"引用就是指针"。
两种都不完全准确。

标准层面：标准**没有规定**引用必须或不必占用存储空间，这是实现自由。
实现层面：编译器通常用指针实现引用，所谓"间接寻址"。所以更准确的说法是 ——
**引用是一种被限制的指针**：底层实现相同，逻辑上的用法不同
（类似线性表和栈的关系，栈是被限制的线性表）。

被限制掉的是两件事：不能为空、不能改指向。编译器阻止对引用本身的任何访问，
它从一而终指向初始的目标。

那到底占不占内存？答案是**看场景**：

```cpp
int x = 0;
int& r = x;
sizeof(r);            // 4，返回的是 int 的大小（语言规定），不是引用的大小

struct WithRef { int& r; ... };   // 作为成员时
sizeof(WithRef);      // 8，确实占了一个指针
```

实测输出：

```
sizeof(int)=4 sizeof(r)=4  <- 取的是 int 的大小
sizeof(WithRef)=8 sizeof(WithPtr)=8  <- 引用成员占一个指针
```

局部的 `int& r = x;` 几乎总会被编译器优化掉（直接当 `x` 用），
而类成员引用必须占空间（因为对象可能被拷贝、存进容器）。
所以"引用不占内存"这句话只在"局部引用通常被优化掉"的意义上成立。

## 四、引用做函数参数

这是引用**最主要的用途**。单纯给变量取个别名几乎没有意义，
引用的价值在于解决参数传递中大对象的效率问题。

三种传参方式的对比（`Tracer` 类在拷贝构造里打了日志）：

```cpp
void by_value(Tracer t)        { /* ... */ }   // 值传递
void by_cref(const Tracer& t)  { /* ... */ }   // const 引用
void by_ptr(const Tracer* t)   { /* ... */ }   // 指针
```

实测输出：

```
值传递（注意有拷贝构造）:
  [拷贝构造] obj
  by_value: obj
const 引用传递（无拷贝）:
  by_cref:  obj
指针传递（无拷贝，但要解引用）:
  by_ptr:   obj
```

值传递会在内存中开辟空间存储形参，把实参的值拷贝过去 ——
形参只是实参的副本。如果传的是类对象，还会调用拷贝构造函数。
对象大的时候很不划算。

引用传参时，形参就是实参的别名，函数内对形参的操作就是对实参本身的操作。
效果和指针传参相当，但**指针传参仍然需要为指针变量分配空间**，引用不需要。
所以 C++ 推荐用引用而非指针作为函数参数。

### 什么时候用哪种

| 方式 | 适用 |
|---|---|
| `const T&` | 默认选择：只读、不想拷贝的大对象 |
| `T&` | 需要修改实参 |
| `T` | 基本类型（`int`/`double`/指针），或确实需要副本 |
| `T*` | 参数可以为空（表达"可选"）、需要指针算术、或要和 C 接口对接 |
| `T&&` | 需要移动语义，见 [02-03](../part2_memory/02-03_move_semantics.md) |

注意小对象别无脑用 `const T&`：传 `const int&` 比传 `int` 更慢
（多一层间接寻址，还可能阻止优化）。经验阈值是**两个指针大小以内的可拷贝类型直接传值**。

### 引用与指针的选择：表达"是否可空"

这是实践中最有价值的一条区分：

```cpp
void must_have(Config& cfg);       // 调用方必须提供有效对象
void may_be_null(Config* cfg);     // 可以传 nullptr 表示"没有"
```

函数签名本身就成了文档。用引用时，函数体内不需要写任何空检查 ——
这不是偷懒，而是把检查义务明确地推给了调用方。

## 五、引用做返回值

```cpp
类型 & 函数名(形参列表) { 函数体 }
```

返回引用意味着"不产生副本"，但有一条硬性前提：
**返回的对象，其生命周期必须长于函数本身** —— 函数执行完毕后它还得存在。

```cpp
int g_number = 0;

int  return_by_value() { g_number = 100;  return g_number; }  // 返回副本
int& return_by_ref()   { g_number = 1000; return g_number; }  // 返回别名

return_by_ref() = 2000;   // 返回引用，所以能当左值
```

实测输出：

```
return_by_value() = 100
给返回的引用赋值后 g_number = 2000
```

### 两条禁令

**1. 不能返回局部变量的引用**

```cpp
int& bad() {
    int local = 1;
    return local;      // local 在函数返回后销毁 -> 悬垂引用
}
```

返回的引用成了"无所指"的引用，程序进入未定义行为。
GCC 会给出 `-Wreturn-local-addr` 警告 —— 这个警告必须当错误对待。

**2. 不要返回函数内 `new` 出来的对象的引用**

```cpp
int& leaky() {
    int* p = new int(1);
    return *p;
}

void test() {
    int c = 2 + leaky() + 4;   // 内存泄漏：拿不到指针，无法 delete
}
```

返回的引用如果只作为临时值使用，而没有被赋给一个实际的变量，
那块空间就再也没机会释放了。需要堆对象时，返回智能指针
（见 [02-05](../part2_memory/02-05_smart_pointers.md)）。

### 引用返回的正当用途

**链式调用** —— 返回 `*this`：

```cpp
class Builder {
public:
    Builder& add(const std::string& part) { _result += part; return *this; }
private:
    std::string _result;
};

b.add("hello").add(", ").add("world");
```

这也是 `operator=`、`operator<<`、`operator+=` 返回引用的原因 ——
不返回引用就没法连写 `a = b = c` 或 `cout << x << y`。

**下标访问** —— 返回元素引用，使其可以作为赋值目标：

```cpp
int& operator[](std::size_t i)             { return _data[i]; }  // 可写
const int& operator[](std::size_t i) const { return _data[i]; }  // 只读

arr[0] = 10;   // 因为返回 int&，才能赋值
```

## 六、const 引用的两个特权

`const T&` 不只是"只读的引用"，它比 `T&` 多两种能力。

**1. 可以绑定临时对象，并延长其寿命**

```cpp
const std::string& ref = make_string();   // 临时量寿命延长到 ref 的作用域
// std::string& bad = make_string();      // 编译错误
```

**2. 可以绑定需要隐式转换的实参**

```cpp
void takes_cref(const std::string& s);

takes_cref("字面量");        // const char* -> 临时 string -> 绑定成功
```

实测输出：

```
  收到: 字面量
  收到: 临时对象
const int& r = 42 -> 42
const int& ri = 3.14 -> 3  (发生了转换，ri 绑的是临时量)
```

最后一行值得留意：`const int& ri = d;`（`d` 是 `double`）能编译通过，
但 `ri` 绑定的是一个 `int` 临时量，不是 `d`。改 `d` 不会影响 `ri`，反之也不会。
这类"看着像引用，其实是独立副本"的情况，是隐式转换引发的隐蔽 bug 来源。

这两个特权正是 `const T&` 成为默认传参方式的原因：它能统一接受左值、右值、
以及可转换的类型，调用方完全不必关心。

## 七、引用做不到的事

引用不能完全替代指针：

| 需求 | 引用 | 指针 |
|---|---|---|
| 可以为空 | 不行 | 可以 |
| 改变指向 | 不行 | 可以 |
| 指针算术 / 遍历数组 | 不行 | 可以 |
| 放进容器 | `std::vector<int&>` 非法 | 可以（或用 `std::reference_wrapper`） |
| 多级间接 | 没有"引用的引用" | `int**` |
| 延迟初始化 | 不行（必须声明时绑定） | 可以 |

需要把引用放进容器时，用 `std::reference_wrapper`（`std::ref`），
见 [06-02 可调用对象](../part6_modern_core/06-02_callable.md)。

## 八、小结

| 要点 | 说明 |
|---|---|
| 本质 | 被限制的指针：不可空、不可改指向；汇编层面是间接寻址 |
| 必须初始化 | 声明时就要绑定 |
| 绑定后不可改 | `ref = x` 是赋值，不是重新绑定 |
| `sizeof` | 返回被引用对象的大小；作为类成员时占一个指针 |
| 主要用途 | 函数参数，避免大对象拷贝 |
| 做返回值 | 被返回对象的寿命必须长于函数；禁止返回局部变量引用 |
| `const T&` | 可绑临时量并延长其寿命、可接受隐式转换 |
| 对比指针 | 可读性更好、无需防空；但不能为空、不能改指向、不能做指针算术 |

引用总结（源自参考文档，仍然准确）：

1. 单纯给某个变量取个别名毫无意义，引用的目的主要在于**解决函数参数传递中
   大块数据或对象的传递效率和空间问题**
2. 用引用传参不产生副本，提高效率，再通过 `const` 保证安全性
3. 指针需要间接操作，程序可读性差；引用本身就是目标变量的别名，
   对引用的操作就是对目标变量的操作
