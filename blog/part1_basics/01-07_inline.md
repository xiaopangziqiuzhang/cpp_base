# 01-07 inline 函数

> 标准：`inline` 函数 C++98、`inline` 变量 `[C++17]`
> demo：[`01_07_inline.cpp`](../../demos/part1_basics/01_07_inline.cpp)

## 一、解决了什么问题

考虑求两个整数最大值：

```cpp
int max(int x, int y) { return x > y ? x : y; }
```

为这么小的操作写一个函数，好处是明确的：

- 读 `max(a, b)` 比读一条等价的条件表达式容易得多
- 需要修改时，改一处函数比找出并修改每一处等价表达式容易
- 使用函数确保了统一的行为，每次调用都以相同方式实现
- 函数可以重用，不必为其他场景重写

但有个潜在缺点：**调用函数比求解等价表达式慢得多**。
在大多数机器上，调用函数要做不少工作 —— 调用前保存寄存器、返回时恢复、
复制实参、跳转到新位置执行。对这种只有一个比较操作的函数，调用开销可能超过函数体本身。

C 的办法是带参数的宏：

```c
#define MAX(a, b) ((a) > (b) ? (a) : (b))
```

预处理器用拷贝宏代码的方式取代函数调用，省去了参数压栈、CALL 指令、
返回值传递、`return` 执行等过程，从而提高速度。

代价是：**宏不是函数，却被当函数用**，于是出现一堆意想不到的边际效应。

## 二、宏的四个问题

### 问题一：优先级

```cpp
#define MAX(a, b) (a) > (b) ? (a) : (b)     // 外层没加括号

int result = MAX(i, j) + 2;
```

展开成：

```cpp
int result = (i) > (j) ? (i) : (j) + 2;
```

因为 `+` 的优先级高于 `?:`，这并不等价于期望的 `((i)>(j)?(i):(j)) + 2`。
实测：`i=5, j=3` 时得到 `6`，而正确答案是 `8`。

把宏改成 `#define MAX(a, b) ((a) > (b) ? (a) : (b))` 可以解决优先级问题。

### 问题二：参数多次求值（加括号也救不了）

```cpp
#define MACRO_MAX(a, b) ((a) > (b) ? (a) : (b))     // 括号加全了

int i = 5, j = 3;
int r = MACRO_MAX(i++, j);
```

展开成 `((i++) > (j) ? (i++) : (j))` —— **`i` 在同一个表达式中被求值两次**。

实测对比：

```
  MACRO_MAX(i++, j): 结果=6 i=7（i 被自增两次）
  inline_max(i++, j): 结果=5 i=6（只求值一次）
```

函数的实参只求值一次，这是语言保证的。宏做不到，而且这类 bug 不会报错，
只会算错，在代码审查里也极难发现。

### 问题三：没有类型检查

```cpp
MACRO_SQUARE(2.5)      // 6.25  —— 宏按 double 算
inline_square(2.5)     // 4     —— 函数签名是 int，发生了转换
```

宏不做类型检查，也不做类型转换。看起来"宏更聪明"，但实际上这意味着
**宏的行为取决于调用点传入什么**，无法从定义处推断。
需要泛型时，正确的工具是模板（见 [Part 5](../part5_template/)），而不是宏。

### 问题四：不可调试，且无法访问类的私有成员

宏在预处理阶段就被替换掉了，符号表里没有它，调试器无从下手。

内联函数**可以调试**。这里要解释一下：不是说展开后还能调试，
而是在程序的 Debug 版本里它根本就没有真正内联 ——
编译器像普通函数那样为它生成含调试信息的可执行代码。
只在 Release 版本里，编译器才实施真正的内联。有的编译器可以设置函数内联开关（如 MSVC）。

对 C++ 而言，宏还有一个缺点：**无法操作类的私有数据成员**。

```cpp
class Counter {
public:
    inline int doubled() const { return _value * 2; }   // 能访问 _value
private:
    int _value;
};
```

成员函数可以访问私有成员，宏不行。

## 三、inline 函数：既有宏的效率，又有函数的安全

定义函数时，在最前面用关键字 `inline` 声明：

```cpp
inline int max(int x, int y) { return x > y ? x : y; }
```

编译器处理内联函数的过程是这样的：

对任何内联函数，编译器在符号表里放入函数的声明 —— 名字、参数类型、返回值类型。
如果编译器没有发现内联函数存在错误，该函数的代码也被放入符号表。
在调用一个内联函数时，编译器首先检查调用是否正确（进行类型安全检查，
或进行自动类型转换，和所有函数一样）。如果正确，内联函数的代码就直接替换函数调用语句，
于是省去了函数调用的开销。

这个过程与预处理器有显著不同，因为预处理器不能进行类型安全检查和自动类型转换。
假如内联函数是成员函数，对象的地址（`this`）会被放在合适的地方，这也是预处理器办不到的。

所以 C++ 的函数内联机制**既具备宏代码的效率，又增加了安全性，而且可以自由操作类的数据成员**。
结论：在 C++ 程序中应该尽量用内联函数取代宏代码。

内联的另一个好处：函数被内联后，编译器可以通过上下文相关的优化技术
对结果代码执行更深入的优化。这种优化在普通函数体内无法单独进行 ——
一旦进入函数体，它就脱离了调用环境的上下文。

### 唯一的例外：assert

`assert` 恐怕是唯一该保留宏形式的例外。它必须是宏，原因有两个：

1. 它需要 `__FILE__` 和 `__LINE__`。函数拿不到**调用点**的文件名和行号
2. 它需要在 Release 版本（定义了 `NDEBUG`）里**完全消失**。
   如果 `assert` 是函数，函数调用会引起内存和代码的变动，
   导致 Debug 版本与 Release 版本存在差异，这并非我们所期望的

实测输出：

```
  assert 需要 __FILE__/__LINE__ 和 NDEBUG，只能是宏
  当前编译未定义 NDEBUG，assert 生效
```

C++20 的 `std::source_location` 部分解决了第 1 点，但第 2 点仍然需要宏。

## 四、inline 必须和定义体放在一起

关键字 `inline` **必须与函数定义体放在一起**才能使函数成为内联，
仅将 `inline` 放在函数声明前面不起任何作用：

```cpp
// 错误：foo 不会成为内联函数
inline void foo(int x, int y);        // 头文件里的声明
void foo(int x, int y) { /* ... */ }  // .cpp 里的定义，没有 inline

// 正确
inline void bar(int x, int y) { /* ... */ }   // 头文件里，声明+定义一体
```

所以 `inline` 是一种"**用于实现的关键字**"，而不是"用于声明的关键字"。

一般来说，用户可以阅读函数的声明，但看不到函数的定义。
尽管大多数教科书在内联函数的声明和定义体前面都加了 `inline`，
但更合理的做法是 `inline` 不出现在函数声明中 ——
这个细节不影响功能，但体现了一个基本原则：
**声明与定义不可混为一谈，用户没有必要、也不应该知道函数是否需要内联。**

### 为什么内联函数要定义在头文件里

这一点不同于其他函数。编译器在调用点内联展开函数代码时，
**必须能够找到函数的定义**才能把调用替换为函数体 —— 仅有函数声明是不够的。

内联函数定义也可以放在源文件中，但此时只有那个源文件能用它，
而且必须为每个需要它的源文件拷贝一份完全相同的定义。
即使放在头文件中，本质上也是对每个翻译单元做一份拷贝，
只不过是编译器替你完成这种拷贝。

相比放在源文件中，放在头文件中既能确保所有调用点看到的定义相同，
又能保证在调用点能找到定义从而完成内联。

## 五、inline 的现代语义：它主要是个链接属性

这是本章最重要的一节，也是多数教材没讲清楚的部分。

在现代 C++ 里，`inline` 对"是否展开代码"的影响**微乎其微** ——
编译器会根据函数体自行判断，`-O2` 下它会内联大量没写 `inline` 的小函数，
也会拒绝内联写了 `inline` 的大函数。

实测：

```
  heavy_function(100) = 222750（写了 inline，但编译器可能拒绝内联）
  small_add(1,2) = 3（没写 inline，-O2 下通常会被内联）
```

`inline` 实际保证的是：**允许该函数在多个翻译单元中有相同的定义，
链接器把它们视为同一个实体**（这叫 vague linkage）。

```cpp
// util.h —— 被多个 .cpp 包含
inline const char* helper() { return "ok"; }
```

去掉 `inline` 并被两个 `.cpp` 包含，链接时就会报：

```
multiple definition of 'helper'
```

这才是 `inline` 在工程上的真正用途 —— 它让 **header-only 库**成为可能。
由此还得到一个保证：`inline` 函数内的 `static` 局部变量，
在整个程序中是**同一个实体**（而不是每个翻译单元一份）。
这是 Meyers Singleton 能工作的基础（见
[03-07 单例模式](../part3_class/03-07_singleton.md)）。

### 隐式 inline

有几类函数不写 `inline` 也具有 inline 语义：

- **在类内部定义的成员函数**（这是最常用的一条）
- 类内定义的友元函数
- `constexpr` 函数（隐式 inline）
- 函数模板的实例（机制不同，但效果类似）

```cpp
class Counter {
public:
    int value() const { return _value; }   // 隐式 inline
private:
    int _value;
};
```

### inline 变量 `[C++17]`

同样的链接语义被扩展到变量：

```cpp
// header.h
inline constexpr int kMagic = 42;      // 多个 TU 包含也只有一个实体
```

详见 [01-02 的第十一节](01-02_const_constexpr.md)。

## 六、谨慎使用内联

内联能提高执行效率，为什么不把所有函数都定义成内联？
如果所有函数都是内联函数，还用得着 `inline` 这个关键字吗？

内联不是万灵丹，它**以代码膨胀（拷贝）为代价**，仅仅省去函数调用的开销。
注意这里说的"函数调用开销"不包括执行函数体所需的开销，
而仅指参数压栈、跳转、退栈和返回等操作。

如果执行函数体内代码的时间比函数调用开销大得多，那么 inline 的效率收益会很小。
另一方面，每一处内联函数的调用都要拷贝代码，使程序总代码量增大，消耗更多内存空间。

**以下情况不宜使用内联：**

1. 函数体内代码比较长 —— 会导致可执行代码膨胀过大
2. 函数体内出现循环或其他复杂控制结构 ——
   执行函数体的时间远大于调用开销，内联意义不大
3. **构造函数和析构函数** —— 不少人误以为让它们成为内联更有效。
   殊不知构造函数和析构函数会隐藏一些行为，
   如"偷偷地"调用基类或成员对象的构造函数和析构函数。
   所以不要轻易让构造函数和析构函数成为内联函数
4. 虚函数 —— 动态绑定的调用无法在编译期确定目标，通常无法内联
   （见 [04-07 多态的代价](../part4_oop/04-07_crtp.md)）
5. 递归函数 —— 无法完全展开

实际上，`inline` 在实现时就是**对编译器的一种请求**，
因此编译器完全有权利取消一个函数的内联请求。
一个好的编译器能够根据函数的定义体自动取消不值得的内联
（这进一步说明了 `inline` 不应该出现在函数声明中），
或者自动地内联一些没有 `inline` 请求的函数。
因此，编译器往往选择那些短小而简单的函数来内联。

### 代码膨胀的实际后果

代码膨胀不只是"文件变大"，它会降低**指令缓存命中率**。
一个被内联到 100 个调用点的中等函数，会在 L1i 缓存里占 100 份空间。
现代 CPU 上，缓存失效的代价常常超过函数调用本身 ——
这是"过度内联反而更慢"的原因。

所以别试图靠手写 `inline` 来优化。正确的做法是：先测量，
再用 `-O2`/`-O3` 让编译器决定，必要时用
`__attribute__((always_inline))` / `[[gnu::noinline]]` 做定点干预。

## 七、小结

| 要点 | 说明 |
|---|---|
| 解决什么 | 小函数的调用开销；同时避免宏的各种边际效应 |
| 宏的四个问题 | 优先级、参数多次求值、无类型检查、不可调试且不能访问私有成员 |
| 唯一该用宏的场合 | `assert`（需要 `__FILE__`/`__LINE__` 和 `NDEBUG`）|
| 位置要求 | `inline` 必须与**定义体**在一起；声明处写无效 |
| 为什么放头文件 | 调用点必须能看到定义才能展开 |
| **现代语义** | 主要是链接属性（允许多 TU 重复定义），而非"保证展开" |
| 隐式 inline | 类内定义的成员函数、`constexpr` 函数 |
| `inline` 变量 `[C++17]` | 头文件里定义唯一实体 |
| 不宜内联 | 函数体长、含循环、构造/析构函数、虚函数、递归 |
| 本质 | 是**请求**，编译器有权拒绝；也会内联你没标记的函数 |
