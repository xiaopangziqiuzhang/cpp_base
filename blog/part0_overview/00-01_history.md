# 00-01 C++ 的三个时代与标准演进

> demo：[`demos/part0_overview/00_01_standard_probe.cpp`](../../demos/part0_overview/00_01_standard_probe.cpp)

## 一、C++ 为什么会出现

C 语言由贝尔实验室的 Dennis Ritchie 于 1972 年完成。它成功得几乎没有争议：
贴近硬件、运行时开销接近于零、编译器容易实现。但 C 是为"计算机专业人员"设计的，
它要求程序员在每个细节上都精确控制。当软件规模从几千行涨到几十万行，
这种"每个细节都要管"就从优势变成了负担 —— 数据和操作数据的函数散落在不同文件里，
没有语言层面的手段把它们绑在一起。

1979 年 4 月，Bjarne Stroustrup 在贝尔实验室试图分析 UNIX 内核的分布化问题，
他需要一个工具来描述模块、度量网络流量。手头的语言都不合用：
Simula 的类机制很好用但运行太慢，C 快但没有抽象能力。同年 10 月，
他完成了一个叫 Cpre 的预处理器，给 C 加上了类似 Simula 的类。

这就是 C++ 的起点。当时它叫 **C with Classes**，1983 年由 Rick Mascitti 建议改名 C++
（`++` 取自 C 的自增运算符）。

从一开始，这门语言就背着两个互相拉扯的约束，理解它们是理解 C++ 所有设计取舍的钥匙：

1. **在运行时间、代码紧凑性、数据紧凑性上必须能与 C 相媲美** ——
   否则没人会从 C 迁移过来。这条约束直接导致了"零开销抽象"原则：
   你不用的特性，不应该让你付出代价。
2. **尽量不限制语言的应用领域** —— 不预设用户在写什么，
   所以 C++ 里没有强制的垃圾回收、没有强制的运行时、没有统一的对象基类。

Stroustrup 没有把 C++ 做成"C 加几个关键字"，而是广泛借鉴：
类的概念来自 Simula，运算符重载、引用、以及"可以在任何地方声明变量"来自 Algol 68，
`//` 注释来自 BCPL，模板和命名空间来自 Ada，异常来自 Ada、Clu 和 ML。

## 二、三个时代

### 第一阶段：1980 年代 — 1995，面向对象时代

这一阶段的 C++ 基本上是"带类的 C"，核心卖点是封装、继承、多态。
凭借接近 C 的效率，它在工业界迅速占据了相当大的份额。

关键节点：1983 年 8 月第一个 C++ 实现投入使用；1985 年 10 月 CFront 1.0 商业发布，
同月 Stroustrup 完成《The C++ Programming Language》第一版；
1990 年 ANSI C++ 委员会成立，同年 7 月**模板**被加入，11 月**异常**被加入；
1993 年加入运行时类型识别（RTTI）和**命名空间**。

### 第二阶段：1995 — 2000，泛型编程时代

1992 年 HP 实现了第一个 STL，1994 年 2 月标准模板库正式成为 ANSI/ISO C++ 的一部分。
STL 和后来的 Boost 让**泛型编程**在 C++ 中的比重越来越大 ——
人们发现模板不只是"类型参数化"，它是一套独立的编程范式。

1998 年 11 月，第一个 C++ 标准 ISO/IEC 14882:1998（C++98）获批。

同期的外部压力也在增大：Java（1995）、C#（2000）相继出现，
硬件价格大幅下降让"运行效率"不再是唯一考量，C++ 受到了明显冲击。

### 第三阶段：2000 — 至今，多范式时代

以 Loki、MPL 为代表的产生式编程和**模板元编程**出现，
人们发现 C++ 模板系统意外地是图灵完备的，可以在编译期做计算。
这些新技术与原有技术融合，让 C++ 成为当今主流语言中最复杂的一员。

与此同时，C++ 的处境一度不太好。它曾是 Visual Studio 6.0 的首选语言，
但在 .NET Framework 推出之后地位持续下滑。那几年流传着一句话：
"C++ 老矣，尚能编否？"

转折点是 **C++11**。

## 三、标准一览

| 标准 | 文档 | 年份 | 一句话定位 |
|---|---|---|---|
| C++98 | ISO/IEC 14882:1998 | 1998 | 第一个标准，确立类 + 模板 + STL + 异常 |
| C++03 | ISO/IEC 14882:2003 | 2003 | 缺陷修订版，几乎没有新特性 |
| C++TR1 | ISO/IEC TR 19768:2007 | 2007 | 技术报告：库扩展，`shared_ptr`/`regex`/`unordered_*` 的前身 |
| **C++11** | ISO/IEC 14882:2011 | 2011 | **自 1998 以来变化最大的一版**，详见下节 |
| C++14 | ISO/IEC 14882:2014 | 2014 | C++11 的补全版：泛型 lambda、`make_unique`、放宽 constexpr |
| **C++17** | ISO/IEC 14882:2017 | 2017 | 语言层整理 + 库层扩张：结构化绑定、`if constexpr`、`optional`/`variant`、`filesystem` |
| C++20 | ISO/IEC 14882:2020 | 2020 | 概念、ranges、协程、模块（本书不覆盖，仅在对比处提及） |
| C++23 | ISO/IEC 14882:2024 | 2024 | `expected`、`print`、多维下标等 |

标准之外还有一批 **TS（Technical Specification）**，是正式进标准前的试验场：
filesystem TS（2015）、concepts TS（2015）、parallelism TS（2015）、
concurrency TS（2016）、coroutines TS（2017）、ranges TS（2017）。
这些名字后来基本都进了 C++17 或 C++20 —— 看到某个特性有对应的 TS，
通常意味着它已经在真实项目里被检验过一轮了。

## 四、C++11 到底改变了什么

C++11 的意义不在于特性数量，而在于它同时朝两个相反的方向用力，且都成功了。

### 方向一：让 C++ 更好用

C++ 简洁、自由、灵活，这既是它的魅力也是它的门槛。
C++11 从其他主流语言借鉴了一批改善易用性的语法：

- `auto` 让编译器推断类型，省掉手写复杂类型名（→ [01-10](../part1_basics/01-10_auto_decltype.md)）
- **lambda 表达式**让匿名函数成为可能，STL 算法从此真正好用（→ [06-01](../part6_modern_core/06-01_lambda.md)）
- **范围 for** 借鉴自 Java，容器遍历不再需要显式迭代器（→ [01-12](../part1_basics/01-12_range_for.md)）
- **统一初始化** `{}` 统一了各种初始化语法（→ [01-11](../part1_basics/01-11_uniform_init.md)）
- `nullptr` 终结了 `NULL` 的类型混乱（→ [01-06](../part1_basics/01-06_bool_nullptr_enum.md)）
- `override`/`final`/`=default`/`=delete` 让类的意图可以写进代码，由编译器检查

### 方向二：让 C++ 更快

- **右值引用与移动语义**解决了"函数返回大对象必然拷贝"的老问题。
  这是 C++11 最重要的性能特性，它让"按值返回"从昂贵变成几乎免费（→ [02-03](../part2_memory/02-03_move_semantics.md)）
- 标准库用新语法做了大规模改写，容器的性能普遍提升
- **并发支持进标准**：`thread`、`mutex`、`atomic`、`future` 和一套内存模型。
  在此之前，写跨平台多线程 C++ 只能依赖 pthread 或 Boost（→ [Part 8](../part8_concurrency/)）

易用性和性能通常是需要权衡的两端，C++11 的罕见之处在于两边同时推进。
这也是"C++ 王者归来"说法的由来。

## 五、范式的变迁

值得留意的是主流写法本身在变：

- **二十年前**：面向过程、基于对象
- **十年前**：面向对象 + 设计模式，深继承体系、大量虚函数
- **现在**：有"返璞归真"的趋势。过度使用虚函数的庞大类继承体系逐渐被摒弃，
  用泛型、函数式等范式开发精致的小类并良好组合，成为大方向

STL 和 Boost 就是这种现代风格的范例，特别是 Boost ——
它不使用复杂的继承体系，而是用泛型编程、模板元编程和编译期静态多态来构建组件。

这个变化对读者的实际影响是：如果你在老教材里学到"面向对象三大特性"就是 C++ 的全部，
那会错过现在最常用的那部分。本书把继承多态（[Part 4](../part4_oop/)）
和泛型（[Part 5](../part5_template/)）放在同等地位，并在
[04-07](../part4_oop/04-07_crtp.md) 专门讨论什么时候**不该**用虚函数。

## 六、动手确认你的编译器

每个标准都有对应的 `__cplusplus` 宏值，C++20 起还有一套
`__cpp_xxx` 特性测试宏，可以精确判断单个特性是否可用：

```cpp
#include <iostream>
int main() {
    std::cout << "__cplusplus = " << __cplusplus << "\n";
#ifdef __cpp_structured_bindings
    std::cout << "structured bindings: " << __cpp_structured_bindings << "\n";
#endif
}
```

对应 demo 会打印出当前标准和一批特性宏，本机 g++ 11.4 的实测结果：

```
__cplusplus = 201703   (-std=c++17)
__cplusplus = 201402   (-std=c++14)
__cplusplus = 201103   (-std=c++11)
```

注意 MSVC 的 `__cplusplus` 默认恒为 `199711L`，需要加
`/Zc:__cplusplus` 才会报告真实值 —— 这是个常见的踩坑点。

## 七、小结

- C++ 的全部设计取舍都源于两条约束：**效率不输 C**、**不限制应用领域**
- 三个时代对应三种主导范式：面向对象 → 泛型 → 多范式融合
- C++98 确立基础，C++11 是分水岭，C++14 补全 C++11，C++17 做整理和库扩张
- 现代 C++ 的方向是"小类 + 泛型 + 组合"，而不是"深继承 + 虚函数"
