# 06-04 C++14 特性汇总

> demo：[`06_04_cpp14.cpp`](../../demos/part6_modern_core/06_04_cpp14.cpp)
> （该 demo 用 `-std=c++14` 编译，实测 `__cplusplus = 201402`）

C++14 是个**小版本**。它的定位不是引入新范式，而是**补全 C++11 的缺口** ——
C++11 规模太大，有些特性来不及打磨，有些明显的组合被漏掉了。

验证这一点的最直接方式：把本章的 demo 用 `-std=c++11` 编译，看报什么错。
实测（去重后）：

```
error: body of 'constexpr' function 'constexpr int factorial_cxx14(int)' not a return-statement
error: body of 'constexpr' function 'constexpr int fib(int)' not a return-statement
error: assignment of member 'Point::_x' in read-only object
error: invalid return type 'void' of 'constexpr' function
error: expected ',' or ';' before '\x30303030'          <- 数字分隔符
error: expected primary-expression before 'int'          <- 泛型 lambda
error: expansion pattern 'int' contains no parameter packs
```

每条错误都对应一个 C++14 新增的能力。下面逐个讲。

## 一、函数返回类型推导

C++11 需要尾置返回类型，C++14 可以完全省略：

```cpp
// C++11
template <class T, class U>
auto add(T a, U b) -> decltype(a + b) { return a + b; }

// C++14
auto add(int a, int b) { return a + b; }
```

实测 `add(20, 22)` 返回 42。

要点：

- **函数定义必须对调用点可见**（因为要推导），所以不适合放在只有声明的头文件接口里
- 多个 `return` 必须推导出**相同的类型**
- **递归函数**需要先有一个能确定类型的 `return`，或者先声明返回类型

```cpp
auto factorial(int n) -> long long;        // 先声明
auto factorial(int n) -> long long {       // 再定义
    return n <= 1 ? 1 : n * factorial(n - 1);
}
```

### decltype(auto)

`auto` 作返回类型会**丢掉引用和 const**。`decltype(auto)` 保留：

```cpp
std::vector<int> g_data{1, 2, 3};

auto           get_by_auto()     { return g_data[0]; }   // int，副本
decltype(auto) get_by_decltype() { return g_data[0]; }   // int&，引用

get_by_decltype() = 42;        // 能写回原容器
```

实测确认类型分别是 `int` 和 `int&`，赋值成功改到了 `g_data[0]`。

详见 [01-10](../part1_basics/01-10_auto_decltype.md)。

## 二、泛型 lambda

C++11 的 lambda 参数类型必须写死，C++14 允许 `auto`：

```cpp
auto add = [](auto a, auto b) { return a + b; };

add(1, 2);                            // 3
add(1.5, 2.5);                         // 4.0
add(std::string("ab"), "cd");          // "abcd"
```

实测三种类型都正确。它等价于带模板 `operator()` 的类。

C++11 下这行代码的报错是 `expected primary-expression before 'int'` ——
编译器根本不认 `auto` 作为参数类型。

详见 [06-01](06-01_lambda.md)。

## 三、初始化捕获（广义 lambda 捕获）

C++11 的捕获只能拷贝或引用，**不能移动**：

```cpp
auto ptr = std::make_unique<int>(42);
// auto bad = [ptr] { return *ptr; };             // 编译错误：unique_ptr 不可拷贝
auto good = [p = std::move(ptr)] { return *p; };  // C++14：移动进 lambda
```

实测可行，原 `ptr` 变成空。

这个缺口在 C++11 里很痛 ——
`unique_ptr`、`thread`、大对象都没法移进 lambda，
只能退回到手写函数对象类。

三个用途（详见 [06-01](06-01_lambda.md)）：

```cpp
[p = std::move(ptr)]       // 移动捕获
[y = x * 2]                 // 捕获表达式结果
[&r = x]                    // 改名/改变捕获方式
```

## 四、std::make_unique

C++11 提供了 `make_shared` 但**漏了** `make_unique` ——
这是个纯粹的疏漏，C++14 补上：

```cpp
auto p1 = std::make_unique<int>(42);
auto p2 = std::make_unique<std::vector<int>>(5, 7);
auto arr = std::make_unique<int[]>(10);
```

实测全部正常。

为什么重要：它让"完全不写裸 `new`"成为可能。
C++11 下用 `unique_ptr` 必须写 `std::unique_ptr<T>(new T(...))`，
而那个裸 `new` 既难看又有异常安全隐患（见
[02-05](../part2_memory/02-05_smart_pointers.md)）。

## 五、变量模板

C++11 要模板化一个常量，只能用函数或结构体包一层：

```cpp
// C++11
template <class T> constexpr T pi() { return T(3.14159...); }        // 要写 ()
template <class T> struct Pi { static constexpr T value = ...; };    // 要写 ::value

// C++14
template <class T> constexpr T pi = T(3.14159265358979323846L);
pi<float>, pi<double>                                                 // 直接用
```

实测两种精度正确。

最重要的应用是 **C++17 的 `_v` 后缀**（见 [06-03](06-03_using.md)）——
`std::is_same_v` 就是变量模板。所以这个 C++14 特性是 C++17 可读性改进的前提。

详见 [05-02](../part5_template/05-02_class_template.md)。

## 六、放宽的 constexpr

这是 C++14 最有实质影响的改动。

C++11 的 `constexpr` 函数体基本只能有**一条 return 语句** ——
不能有局部变量、循环、if 语句：

```cpp
// C++11：只能这么写
constexpr int factorial(int n) {
    return n <= 1 ? 1 : n * factorial(n - 1);
}
```

C++14 允许局部变量、循环、分支：

```cpp
constexpr int factorial(int n) {
    int result = 1;
    for (int i = 2; i <= n; ++i) result *= i;      // C++11 下编译错误
    return result;
}

constexpr int fib(int n) {
    if (n <= 1) return n;                           // C++14 起可以用 if
    int a = 0, b = 1;
    for (int i = 2; i <= n; ++i) { int t = a + b; a = b; b = t; }
    return b;
}
```

C++11 的报错很直白：

```
error: body of 'constexpr' function 'constexpr int factorial_cxx14(int)'
       not a return-statement
```

还放宽了 `constexpr` 成员函数 —— 可以是非 const 的，可以修改成员：

```cpp
class Point {
public:
    constexpr Point(int x, int y) : _x(x), _y(y) {}
    constexpr void move(int dx, int dy) { _x += dx; _y += dy; }   // C++14
private:
    int _x, _y;
};

constexpr Point translate(Point p, int dx, int dy) { p.move(dx, dy); return p; }
constexpr Point moved = translate(Point(0, 0), 3, 4);
static_assert(moved.x() == 3, "");
```

C++11 下的报错：

```
error: invalid return type 'void' of 'constexpr' function
error: assignment of member 'Point::_x' in read-only object
```

（C++11 里 `constexpr` 成员函数隐式是 const 的，所以不能改成员。）

### 这个放宽的意义

它把**编译期计算从模板元编程的黑魔法变成了普通代码**。

对比同一个计算的两种写法：

```cpp
// C++98/11：模板元编程
template <int N> struct Factorial { static constexpr int value = N * Factorial<N-1>::value; };
template <> struct Factorial<0> { static constexpr int value = 1; };

// C++14：就是普通函数
constexpr int factorial(int n) { int r = 1; for (int i = 2; i <= n; ++i) r *= i; return r; }
```

后者可读、可调试、编译更快（见
[05-06 的实测](../part5_template/05-06_template_engineering.md)：
内存差 4.7 倍）。

**所以 C++14 之后，编译期计算优先用 `constexpr` 函数，不要用模板递归。**

详见 [01-02](../part1_basics/01-02_const_constexpr.md)。

## 七、[[deprecated]] 属性

```cpp
[[deprecated("请改用 new_api()")]]
void old_api();

[[deprecated]] int old_constant = 42;
```

使用时产生警告：

```
warning: 'void old_api()' is deprecated: 请改用 new_api()
```

可以用在函数、变量、类、枚举、枚举值、命名空间、typedef 上。

价值：**把废弃信息从注释变成编译器警告**。
库演进时这是标准做法 —— 用户升级库版本后会立刻看到提示，
而不是等到接口被删除才发现。

详见 [01-09](../part1_basics/01-09_literals.md)。

## 八、数字分隔符与二进制字面量

```cpp
int binary = 0b1010'1010;            // 二进制字面量（C++14 标准化）
int million = 1'000'000;              // 数字分隔符
constexpr unsigned mask = 0b1111'0000'1111'0000;
```

实测分别是 170、1000000、61680。

C++11 下的报错很奇怪：

```
error: expected ',' or ';' before '\x30303030'
```

编译器把 `'000'` 当成了字符字面量 —— 因为单引号在 C++11 里只能是字符。

注意：**二进制字面量 `0b` 是 GCC 的扩展，C++14 才标准化**。
所以 `-std=c++11` 下 GCC 可能接受它（但 `-pedantic` 会警告）。

详见 [01-09](../part1_basics/01-09_literals.md)。

## 九、标准库字面量后缀

```cpp
using namespace std::string_literals;
using namespace std::chrono_literals;

auto s = "hello"s;        // std::string（不是 const char*）
auto d = 500ms;            // std::chrono::milliseconds
auto h = 2h;
```

实测：

```
      "hello"s 的类型是 string: 1
      "hello"s + ", world" = hello, world
      500ms = 500 ms
      2h 换算成分钟 = 120
```

`s` 后缀省掉了显式构造 `std::string`。
chrono 后缀让时间单位进入类型系统，传错单位是编译错误。

详见 [01-09](../part1_basics/01-09_literals.md)
和 [07-05](../part7_stdlib/07-05_chrono_random.md)。

## 十、库层面的小改进

### std::exchange

设新值并返回旧值：

```cpp
int x = 1;
int old = std::exchange(x, 100);      // old == 1, x == 100
```

最常见的用途是**实现移动构造函数**：

```cpp
// 不用 exchange
MyClass(MyClass&& rhs) noexcept : _ptr(rhs._ptr) { rhs._ptr = nullptr; }

// 用 exchange：一行，不会漏掉置空
MyClass(MyClass&& rhs) noexcept : _ptr(std::exchange(rhs._ptr, nullptr)) {}
```

后者更不容易出错 —— "接管资源"和"源对象放弃"是一个表达式，不可能漏掉第二步
（见 [02-03](../part2_memory/02-03_move_semantics.md)）。

### std::integer_sequence / make_index_sequence

编译期整数序列，用于展开 tuple 等：

```cpp
template <class Tuple, std::size_t... Is>
void print_tuple_impl(const Tuple& t, std::index_sequence<Is...>) {
    ((std::cout << std::get<Is>(t) << " "), ...);
}

template <class... Ts>
void print_tuple(const std::tuple<Ts...>& t) {
    print_tuple_impl(t, std::make_index_sequence<sizeof...(Ts)>{});
}
```

这是 C++17 的 `std::apply` 的实现基础。
C++14 之前要自己手写这个序列生成器。

### 其他

- **异构查找**：`std::set`/`map` 的 `find` 可以接受可比较但不同类型的键
  （需要透明比较器 `std::less<>`）
- `std::quoted`：带引号的字符串 IO
- `std::cbegin`/`cend`/`rbegin`/`rend` 自由函数
- `std::tuple_element_t`、`std::result_of_t` 等一批 `_t` 别名

## 十二、小结

C++14 的定位是**补全**：

| C++11 的缺口 | C++14 的补丁 |
|---|---|
| 返回类型必须写尾置形式 | 完全省略 |
| `auto` 返回丢引用 | `decltype(auto)` |
| lambda 参数类型写死 | 泛型 lambda |
| lambda 不能移动捕获 | 初始化捕获 |
| 有 `make_shared` 没 `make_unique` | 补上 |
| 常量不能模板化 | 变量模板 |
| `constexpr` 只能一条 return | 允许循环和分支 |
| 废弃信息只在注释里 | `[[deprecated]]` |
| 长数字难读 | 数字分隔符 |

**升级到 C++14 的成本极低、收益明确**：没有破坏性改动，
全部是补齐常用组合。如果你的项目还在 C++11，这是最容易的一次升级。

单论特性数量它远不如 C++11 和 C++17，但**放宽的 `constexpr`**
和**泛型 lambda** 这两项改变了实际的编码方式。
