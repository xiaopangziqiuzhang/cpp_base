# 06-05 C++17 语言特性汇总

> demo：[`06_05_cpp17.cpp`](../../demos/part6_modern_core/06_05_cpp17.cpp)

C++17 的定位介于 C++11 和 C++14 之间：**没有 C++11 那样的范式级改动，
但有一批实质改善日常编码的语言特性，以及大量库扩展**。

本章讲语言特性，库特性（`optional`/`variant`/`string_view`/`filesystem`/
并行算法）在 [Part 7](../part7_stdlib/) 展开。

## 一、结构化绑定

给聚合对象的各个部分起名字：

```cpp
struct Record { int id; std::string name; double score; };

Record r{1, "alice", 95.5};
auto [id, name, score] = r;        // 分别绑定三个成员
```

三种来源（详见 [01-12](../part1_basics/01-12_range_for.md)）：

```cpp
auto [a, b] = std::make_pair(1, "two");     // tuple-like
int arr[3]{10, 20, 30};
auto [x, y, z] = arr;                        // 数组
auto [id, name, score] = r;                  // 全 public 成员的聚合类
```

实测全部正确。

最常用的两个场景：

```cpp
// 遍历 map
for (const auto& [k, v] : m) { use(k, v); }      // 不再写 .first / .second

// 接住返回多个值的函数
auto [iter, inserted] = m.insert({"z", 3});
```

绑定引用可以写回：

```cpp
auto& [rid, rname, rscore] = r;
rid = 99;                 // 修改了 r.id
```

实测 `r.id` 变成 99。

## 二、if / switch 初始化语句

```cpp
if (auto it = config.find("timeout"); it != config.end()) {
    use(it->second);
}
// it 在这里不可见
```

分号前是初始化语句，分号后是条件。价值是**把变量的作用域限制在 if/switch 内**，
避免污染外层作用域。

和结构化绑定组合是现代 C++ 最常见的写法之一：

```cpp
if (auto [it, ok] = config.insert({"retries", 3}); ok) {
    std::cout << it->first << " = " << it->second;
}
```

`switch` 同样支持：

```cpp
switch (int n = get_count(); n) {
    case 2:  /* ... */ break;
    default: use(n);
}
```

详见 [01-12](../part1_basics/01-12_range_for.md)。

## 三、if constexpr

**不成立的分支不被实例化**：

```cpp
template <class T>
std::string describe(T value) {
    if constexpr (std::is_integral_v<T>) {
        return "整型: " + std::to_string(value);
    } else if constexpr (std::is_floating_point_v<T>) {
        return "浮点: " + std::to_string(value);
    } else {
        return "其他类型";
    }
}
```

实测三种类型都走对了分支。

这是 C++17 在模板编程上**最实用**的改进 ——
它取代了大量用 SFINAE、`enable_if`、标签分发写的样板代码。

详见 [05-05](../part5_template/05-05_type_traits.md)
和 [01-02](../part1_basics/01-02_const_constexpr.md)。

## 四、折叠表达式

```cpp
template <class... Args> auto sum(Args... args) { return (0 + ... + args); }
template <class... Args> void print_all(Args... args) { ((std::cout << args << " "), ...); }
template <class... Args> bool all_of(Args... args) { return (args && ...); }
```

实测：

```
      sum(1,2,3,4) = 10
      sum() = 0（带初值的折叠能处理空包）
      print_all: 1 a 2.5 str
      all_of(true,true,false) = 0
```

一行替代了 C++11 的"递归 + 终止函数"或"逗号表达式 + 数组 trick"。

详见 [05-04](../part5_template/05-04_variadic.md)。

## 五、CTAD：类模板实参推导

类模板可以从构造函数实参推导模板参数：

```cpp
Box b1(42);                        // Box<int>
std::vector v{1, 2, 3};            // vector<int>
std::pair p(1, 2.5);               // pair<int, double>
std::array arr{1, 2, 3};           // array<int, 3>
std::lock_guard lk(mtx);           // lock_guard<std::mutex>
```

实测类型推导全部正确。

最明显的改善是 `std::lock_guard` ——
C++17 之前必须写 `std::lock_guard<std::mutex> lk(mtx);`，
现在省掉了那个显而易见的模板参数。

效果：`std::make_pair`、`std::make_tuple` 基本可以退休了。
（但 `make_shared`/`make_unique` 仍然必要 —— 它们不只是为了推导。）

详见 [05-02](../part5_template/05-02_class_template.md)。

## 六、内联变量

C++17 之前，在头文件里定义全局常量或静态成员很别扭：

```cpp
// C++17 之前
// header.h
extern const double kPi;                    // 只能声明
class Widget { static int count; };
// source.cpp
const double kPi = 3.14159;                  // 必须在某个 .cpp 里定义
int Widget::count = 0;
```

C++17 的 `inline` 变量：

```cpp
// header.h，仅此一处
inline constexpr double kPi = 3.14159265358979323846;
inline int g_counter = 0;                    // 非 const 的也行

class WithStatic {
public:
    static inline int instance_count = 0;     // 不需要类外定义！
    static inline const std::string kName = "widget";
};
```

实测：

```
      kPi = 3.14159
      WithStatic::instance_count = 3
      WithStatic::kName = widget
```

**这对 header-only 库意义重大** ——
以前要么强迫用户提供一个 `.cpp`，要么用函数包一层。

详见 [01-02](../part1_basics/01-02_const_constexpr.md)
和 [03-05](../part3_class/03-05_special_members.md)。

## 七、嵌套命名空间简化

```cpp
// C++98
namespace a { namespace b { namespace c { void func(); } } }

// C++17
namespace a::b::c { void func(); }
```

实测可用。细节见 [01-01](../part1_basics/01-01_namespace.md)。

（C++20 进一步允许 `namespace a::b::inline c {}`。）

## 八、保证的拷贝消除

C++17 把**纯右值的拷贝消除从"允许的优化"变成"语言规定"**。

```cpp
Tracer make_tracer() { return Tracer{}; }     // 返回纯右值
Tracer t = make_tracer();
```

实测输出只有一次构造：

```
      从函数返回临时对象:
        Tracer()
      ^ C++17 保证没有任何拷贝/移动（只有一次构造）
```

C++14 下这**也通常**只有一次构造，但那是编译器的可选优化
（可以用 `-fno-elide-constructors` 关掉）。C++17 的区别是：
标准规定了纯右值"直到被用来初始化对象时才具体化"，
所以根本不存在要消除的拷贝。

### 可观察的差别：能返回不可移动的类型

这是 C++17 和 C++14 真正不同的地方：

```cpp
class Immovable {
public:
    Immovable() = default;
    Immovable(const Immovable&) = delete;
    Immovable(Immovable&&) = delete;
};

Immovable make_immovable() { return Immovable{}; }
Immovable im = make_immovable();
```

我单独验证了这一点：

```
--- C++14 ---
error: use of deleted function 'Immovable::Immovable(Immovable&&)'
--- C++17 ---
0  （0 个错误 = 编译成功）
```

C++14 下即使编译器实际会消除拷贝，也**仍然要求拷贝/移动构造函数可用**
（只是不调用它）。C++17 不再需要。

实际意义：

- `std::mutex`、`std::atomic`、`std::lock_guard` 这类不可移动的类型
  可以从工厂函数返回
- `std::optional<T>`、`std::variant` 对不可移动的 `T` 支持更好
- 工厂函数不再需要考虑"返回类型必须可移动"

详见 [02-03](../part2_memory/02-03_move_semantics.md)。

## 九、__has_include

预处理器可以检查头文件是否存在：

```cpp
#if __has_include(<optional>)
#  include <optional>
#  define HAS_OPTIONAL 1
#else
#  define HAS_OPTIONAL 0
#endif
```

实测：

```
      __has_include(<optional>) 为真
      __has_include(<not_a_real_header>) 为假
```

用途：跨标准、跨平台的兼容代码。典型例子是 filesystem
在 GCC 8 及更早版本位于 `<experimental/filesystem>`：

```cpp
#if __has_include(<filesystem>)
#  include <filesystem>
   namespace fs = std::filesystem;
#elif __has_include(<experimental/filesystem>)
#  include <experimental/filesystem>
   namespace fs = std::experimental::filesystem;
#endif
```

本书的 filesystem demo 就用了这个手法（见
[07-06](../part7_stdlib/07-06_regex_filesystem.md)）。

## 十、其他语言特性

### auto 非类型模板参数

```cpp
template <auto kValue>
void show_value();

show_value<42>();        // kValue 是 int
show_value<'x'>();       // kValue 是 char
```

实测类型推导正确。详见 [05-01](../part5_template/05-01_function_template.md)。

### noexcept 成为类型系统的一部分

```cpp
void may_throw() {}
void never_throws() noexcept {}

std::is_same_v<decltype(&may_throw), decltype(&never_throws)>     // false
```

实测确认是不同类型。C++17 之前 `noexcept` 只是个"规格说明"，
不影响函数指针的类型。现在它进入了类型系统，所以：

```cpp
void (*fp)() noexcept = may_throw;      // 编译错误：不能把可能抛的函数赋给 noexcept 指针
void (*fp2)() = never_throws;            // ok：反方向可以（更强的保证能满足更弱的要求）
```

这让"不抛异常"的承诺能被类型系统强制检查。

### 聚合初始化支持基类

```cpp
struct Base { int a; };
struct Derived : Base { int b; };

Derived d{{1}, 2};        // C++17 起可以这样初始化
```

实测 `d.a=1 d.b=2`。C++14 下 `Derived` 因为有基类而不是聚合类型，
无法这样初始化。

### 单参数 static_assert

```cpp
static_assert(sizeof(int) == 4);          // C++17：可以省略消息
static_assert(sizeof(int) == 4, "...");   // C++11：必须有消息
```

实测可用。省略时编译器会输出条件表达式本身。

### 新属性

```cpp
[[nodiscard]]        // 返回值被忽略时警告
[[maybe_unused]]     // 抑制未使用警告
[[fallthrough]]      // switch 中声明故意落穿
```

详见 [01-09](../part1_basics/01-09_literals.md)。

### 其他小改动

- **模板模板参数可以用 `typename`**（以前只能用 `class`）
- **`u8` 字符字面量**：`u8'x'`
- **十六进制浮点字面量**：`0x1.8p3`
- **`constexpr` lambda**（见 [06-01](06-01_lambda.md)）
- **`[*this]` 捕获**（见 [06-01](06-01_lambda.md)）
- **移除的东西**：`register` 关键字、`bool` 的 `++`、
  动态异常规范 `throw(...)`、`std::auto_ptr`、`std::random_shuffle`

## 十二、小结

C++17 语言特性按"日常使用频率"排序：

| 优先掌握 | 为什么 |
|---|---|
| **结构化绑定** | 遍历 map、接多返回值，天天用 |
| **if 初始化语句** | 配合结构化绑定，是新的标准写法 |
| **`if constexpr`** | 彻底改变了模板编程的写法 |
| **CTAD** | 少写模板参数，`lock_guard` 等受益明显 |
| **折叠表达式** | 可变参数模板从难写变成好写 |
| **`static inline` 成员** | header-only 库的关键改进 |

次要但值得知道：保证的拷贝消除（能返回不可移动类型）、
`__has_include`（兼容性代码）、`noexcept` 进类型系统。

**升级到 C++17 的成本依然很低**（移除的东西基本都是早已废弃的），
而库层面的 `optional`/`variant`/`string_view`/`filesystem`
提供的价值相当大。如果环境允许，C++17 是目前最合适的基线标准。
